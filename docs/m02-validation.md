# M02 验收记录

日期：2026-10-20，Asia/Shanghai。范围为 Linux PipeWire 系统输出采集，不包含 ASR 或翻译。

## 已实现

- 独立 `subveil-audio` crate；Linux 实现和 GPUI 分离，其他平台明确拒绝采集。
- 原生 registry / default metadata 检测默认 Audio/Sink，通过 node.name 精确选 monitor，禁止 fallback 到输入源。
- F32LE 单声道 PCM；由调用者指定 8–192 kHz 请求速率，GUI 提供 16 / 24 / 48 kHz；PipeWire 内置 sinc 重采样。
- 固定 16 块队列，每块最多 2048 样本；满时丢最旧块、过期不回放、流切换清除待消费数据，累计丢块和丢样本。
- 校验格式、缓冲边界、stride 和 SPA 标记；损坏数据拒绝，EMPTY 生成等时长静音；NaN / Inf 清零。
- RMS / 峰值 / 静音和设备信息，错误持续可见；服务中断自动重试，默认输出变化或移除自动重建流。
- UI 显式启停采集；停止异步取消，退出线程之前不能启动第二个会话；关闭控制窗口保留采集与恢复入口。
- 无音频文件保存、网络、模型或真实识别。模拟字幕与采集独立。
- `mise run audio:probe -- SECONDS RATE` 提供无窗口诊断，输出统计并等待取消完成。

## 自动检查

`mise run check` 已通过：格式、锁定构建、严格 Clippy、25 项测试。`git diff --check` 通过。

核心用例涵盖队列满淘汰、分块与尾样本、无效长度、非有限值、电平、过期、旧连接代次拒绝、设备 ID 复用、默认设备缺失拒绝回退、流切换清空、SPA EMPTY 静音和采样率范围。原有字幕、配置、CLI 测试保持通过。

## 运行验证

- 本机真实默认 USB 输出收到 48 kHz PCM，实际播放时显示有声，静默时清零；未改变设备音量或系统图采样率。
- 独立 `/tmp` PipeWire 实例使用两个虚拟 sink 和专用合成 WAV，未连接实体扬声器或更改用户路由。测试实例没有会话管理器，测试工具手工配置与连接端口；这不声称应用支持无会话管理器自动连线。
- 44.1 kHz、440 Hz、0.1 峰值测试音经过 48 kHz 图，输出 16 kHz PCM；观测 RMS 约 0.0705–0.0709、峰值约 0.1。停止测试音后约 1 秒内日志显示零电平与静音。
- metadata 从虚拟输出 A 切换 B，连接计数从 1 变为 2；删除 B 后状态变为等待默认输出；恢复 A 后连接计数为 3，重新收到 PCM。
- 仅重启隔离 PipeWire 服务：先显示 connection error / Creation failed 并按秒重试；服务恢复后重建 metadata、registry 与流，24 kHz PCM 样本继续增长，连接计数变为 2。
- 实际启动 GPUI，检查控制窗口截图：音频设备、电平条、RMS / 峰值、静音、计数与采集按钮正常显示。GUI 启动仍有此前已记录的第三方 Vulkan 隐式层错误，窗口正常渲染。
- 30 分钟稳定性未验证。长测在用户纠正后立即终止；该次终止前约 140 秒，未观察到丢块或无效块，不能据此声称长期无泄漏。后续单次测试最多 90 秒。

## 限制

- 当前 PipeWire 1.6.9 / WirePlumber / Hyprland 实测；物理 USB 拔插、蓝牙 profile 变化及其他发行版未逐一验证。
- 隔离测试覆盖服务断开与设备节点移除，不等同所有硬件恢复场景。
- 单调时间是回调接收时间，不是硬件采集 PTS。M03 需要在此基础上定义识别分段与时间对齐。
- M02 的 PCM 消费端只计算本机电平；无字幕识别输出。静音阈值固定，尚无 VAD 或用户阈值设置。
- Linux 以外音频捕获未实现；默认 metadata 缺失时明确等待，不猜选设备、不回退麦克风。
